# opnsense_trust_settings (Resource)

Uses the released OPNsense 26.7.8 Trust general settings API. This increment
covers five Boolean policies and the selected `CipherString` choice keys only.
It does not manage `Ciphersuites`, `SignatureAlgorithms`, `groups`, `MinProtocol`
or `MinProtocol_DTLS`, CA/certificate actions or full Trust lifecycle parity.

## Example Usage

```terraform
# Import existing settings before applying. Omitted arguments preserve appliance policy.
resource "opnsense_trust_settings" "policy" {
  install_crls  = false
  cipher_string = [] # Explicitly clear the selected ciphers.
}
```

## Schema

### Optional

- `cipher_string` (Set of String) Selected OpenSSL CipherString choice keys. Omission preserves policy; an empty set clears.
- `enable_config_constraints` (Boolean) Enable custom OpenSSL configuration constraints. Omission preserves existing policy; explicit false clears.
- `enable_legacy_sect` (Boolean) Enable OpenSSL legacy providers. Omission preserves existing policy; explicit false clears.
- `fetch_crls` (Boolean) Schedule hourly CRL downloads using distribution points from CAs in the trust store. Omission preserves existing policy; explicit false clears.
- `install_crls` (Boolean) Store all configured certificate revocation lists in the default trust store. Omission preserves existing policy; explicit false clears.
- `store_intermediate_certs` (Boolean) Allow locally defined intermediate certificate authorities in the local trust store. Omission preserves existing policy; explicit false clears.

### Read-Only

- `id` (String) Fixed singleton identity trust_settings.

## Adoption and ownership

Create never resets or saves settings: import the exact fixed ID `trust_settings`
first. Omitted fields preserve authoritative appliance/imported/prior policy,
including when removing an argument. There are no static defaults. Explicit
`false` and an empty `cipher_string` set are real clears. Unknown configured
values or members must resolve before any save. Only configured fields are
written under the `trust` envelope; unrelated policy is never echoed back.
Use only one owner for these fields.

The provider needs GET `/api/trust/settings/get`, POST
`/api/trust/settings/set` and POST `/api/trust/settings/reconfigure` permissions.
The global mutation mutex covers baseline, save, read-back and activation.
If an omitted known planned value changed since planning, apply fails before saving;
refresh and create a fresh plan. Nonempty private intent is stored before saving.
Save and activation POSTs are single-attempt and refuse redirects; duplicate,
case-aliased or contradictory outcomes retain pending recovery.
Malformed material fields fail closed instead of silently clearing selections.

## Recovery and destruction

Confirmed or uncertain saves retain fixed identity, known state and canonical
private requested intent. Preserve returned Terraform state and refresh. Recovery
observes authoritative fields before activation and never repeats set. Matching
requested fields permit reconfigure; contradictory truth clears pending intent
without activation and requires a fresh plan. Invalid/unavailable truth retains
pending intent. Validation failures remain errors. Activation requires affirmative
`status=ok`; fixture/protocol success is not appliance or release proof.

Delete itself makes zero HTTP calls, even with pending state or an unavailable
client. It removes ownership only and never resets shared settings. Normal Core
planning refresh before Delete can read, recover or activate pending settings;
an entire `terraform destroy` is not promised to be zero-API. Direct Delete with
pending intent abandons activation, without reverting saved settings.
